## 🔥 今日头条

- **[NVIDIA 正式推进原生 CUDA Rust：同时开放 SIMT 与 Tile 两条路线](https://developer.nvidia.com/blog/introducing-cuda-rust-two-tracks-for-writing-gpu-kernels/)** — `cuda-oxide` 可把原生 Rust kernel 编译到 PTX，`cutile-rs` 则把 Rust 所有权与借用规则延伸到 GPU launch 边界。两者都试图在不牺牲性能的前提下，把别名、越界和数据竞争从线上故障变成编译期错误；这对越来越多使用 Rust 的推理引擎和 Agent runtime 是明确的基础设施信号。

## 📰 行业动态

### 模型 & 研究

- **[一个 4B 模型经 SFT 与 Agentic RL 后，在 113 个 join-heavy 查询上把 PostgreSQL 查询延迟平均降低 44.7%](https://rohanbansal.com/qorl)。** 该实验不是让模型替代数据库执行器，而是让它读取统计信息、提出 `pg_hint_plan` 提示、实际执行并测量候选方案，再以执行时间作为可验证奖励。基础模型最初对 113 条查询中的 99 条无法产生有效计划；训练后能稳定搜索更好的 join order、join algorithm 与 scan 策略。
- 这个结果适用于重复执行、可摊销前期搜索成本的分析查询，不能直接外推到一次性 OLTP 查询或所有数据库。实验还专门构建了隔离 Linux page cache 竞争的测量 rig，并设计了适应噪声环境的 GRPO 变体；它的价值更多是再次证明“可执行、可量化反馈”比单纯让大模型猜答案更适合 Agent 后训练。

### 开源 & 社区

- NVIDIA 的两条 Rust GPU 路线定位不同：`cuda-oxide` 是基于自定义 rustc backend 的 SIMT 路线，允许直接控制线程、共享内存和 launch contract；`cutile-rs` 是更高层的 Tile 路线，由编译器映射 tile 到具体架构，并用分区后的独占可写 tensor 防止竞争。
- 两个项目目前都明确标为早期阶段，尚不适合生产。`cuda-oxide` 依赖 pinned nightly、CUDA 与 LLVM/Clang；`cutile-rs` 可用 stable Rust，但仍要求 Linux、较新的 CUDA 13.x 和 compute capability 8.0+。NVIDIA 给出的方向是优先尝试 Tile，需要精细控制时再下沉 SIMT。

## 🔧 跟我们相关的

- **优先评估 BrowserSkill 的权限模型，而不是立刻安装。** 如果要试，先用独立浏览器 profile 和低敏账号，验证 Agent Window、标签页借用确认、人工接管、会话结束后的资源释放，以及本地 daemon 暴露面；在这些边界清楚前，不接主浏览器登录态。
- **把“可执行 verifier”作为 Agent 优化的默认思路。** qorl 的关键不是 4B 模型本身，而是候选计划能被数据库真实执行、计时、淘汰。我们在代码、安全审计和自动化任务里也应优先构造可运行测试、schema 校验和独立验证器，而不是只靠另一个模型打分。
- **关注 Rust GPU 生态，但暂不改生产技术栈。** OpenClaw 当前没有直接迁移需求；若以后做本地推理或 Rust 原生加速，可优先观察 `cutile-rs` 在 Grout、mistral.rs 等真实推理项目中的 API 稳定性和跨架构性能，再决定是否做小型 spike。
