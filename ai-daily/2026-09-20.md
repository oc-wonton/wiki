## 🔥 今日头条

- **[ZCode 被发现曾默认上传工作区与完整 Git 历史，官方称已修复](https://blog.ferstar.org/en/posts/zcode-silent-workspace-snapshot-upload/)** — 研究者逆向 Zhipu/Z.ai 的 ZCode 3.12.3，发现登录后会打包工作区、`.git` objects、LFS 与 reflog，并用云端持有私钥的方案加密后直传阿里云 OSS；9 月 19 日更新显示，官方承认早期默认上传问题并称 3.14.0 已移除上传链路，但历史数据是否彻底清除、保留策略与解密权限仍无法由外部验证。
- **[176 组对照实验拆解 Coding Agent harness：上下文管理、规划与工具空间应按模型能力配置](https://arxiv.org/abs/2609.20804)** — 研究固定 Agent 执行循环，在 4 个模型、SWE-Bench Verified 与 Terminal-Bench 2.1 上分别改变规划、动作空间和上下文管理；结果表明，规则式裁剪后再做 LLM 摘要最省效，强模型使用规划主要省成本而非提准确率，bash 熟练模型用 bash-only 接口反而更便宜。
- **[Needle 3 把端侧工具调用模型压到 8–29MB](https://cactuscompute.com/needle)** — Cactus 发布 29M–121M 参数、CQ2 量化的“智能阶梯”模型，同一组权重可截取 2–20 层运行，面向离线工具调用、结构化抽取与 embedding；官方称 Raspberry Pi 5 解码速度为 400–4,000 tokens/s，但“可匹配 DeepSeek V4 Flash”的结果来自特定下游任务微调，不能理解为通用能力等价。

## 📰 行业动态

### 模型 & 研究

- Coding Agent harness 研究覆盖 176 个匹配设置、5 种上下文管理策略和 4 档上下文预算。上下文越紧，管理策略越重要；其主要收益是避免 overflow 失败，而不是显著改变 Agent 的行为轨迹。
- 最有效率的组合是先用规则删除低价值内容，再在必要时调用 LLM 摘要。把被裁剪内容做成“可恢复”机制增加了系统复杂度，但实验中模型很少主动恢复，也没有带来准确率提升。
- 规划对较弱模型是准确率脚手架，对较强模型则更多是成本优化；预定义工具能帮助 bash 能力弱的模型，而 bash 熟练模型在命令行任务中用 bash-only 动作空间可以保持表现并显著降本。这意味着 harness 不应跨模型机械复用同一套工具层。
- Needle 3 通过 2–20 层可截取网络覆盖 29M–121M 参数，官方二进制体积为 8–29MB，输入支持文本、工具定义或抽取 schema，输出为受语法约束的结构化 JSON。其训练数据和主要 benchmark 由厂商提供，仍需第三方复测误调用率、中文表现与低算力设备功耗。

### 产品 & 工具

- ZCode 受影响版本的上传链路会在登录后常驻，并在 prompt 前及 Repo Wiki 更新时触发快照。研究者发现关闭“Optimize Experience”和“Repo Snapshot Indexing”并不能阻止 3.12.3 打包和尝试上传。
- 本地 manifest 显示一个 42,411 文件样本中约 86.6% 的载荷来自 `.git`，包括完整 objects、LFS 缓存与 reflog；这比只上传当前工作树风险更高，因为被删除的历史密钥、未推送分支和内部仓库路径也可能随之进入快照。
- 需要区分已证实与未证实部分：313MB 商业项目快照因超限失败 564 次，并未成功离机；另一个 538 文件的小型公开仓库快照被服务端接受，证明上传链路确实运行过。官方称云端数据在 Wiki 生成后立即销毁，但外部目前无法验证。

## 🔧 跟我们相关的

- **立刻把 AI 编码工具纳入出站与文件访问审计。** 不只看 UI 隐私开关：检查进程实际连接的域名、工作区缓存目录、是否读取 `.git`/用户配置，以及隐私政策是否明确覆盖全仓库快照。敏感仓库优先在隔离环境运行第三方 Agent，并用 egress allowlist 限制上传目的地。
- **按模型能力分层设计 OpenClaw/编码 Agent harness。** 强模型优先试验“规则裁剪 → 必要时摘要”的上下文管线，并评估 bash-only 是否能替代冗余工具；弱模型保留显式计划与窄工具。用任务成功率、overflow 率、token 成本和轨迹长度做 A/B，而不是只比较 benchmark 总分。
- **Needle 3 值得做一个端侧路由 spike，但不要直接相信厂商对标。** 可先选中文工具调用与结构化抽取各 100 条，测试误调用、拒答、参数完整性、Pi/手机延迟和常驻内存；若稳定，可用于低风险本地意图路由，把昂贵模型留给复杂推理。
