## 🔥 今日头条

- **[Anthropic 发布 Claude Opus 5.5](https://www.anthropic.com/claude-opus-5-5)** — 新模型在长时编码、计算机操作和知识工作上升级，同时把输入/输出价降到每百万 token 4/20 美元；Anthropic 称典型任务成本较 Opus 5 低 40%、输出快 30% 以上。更重要的是，缓存读取价从 0.50 美元降至 0.20 美元，直接改善长上下文 Agent 的持续运行成本。
- **[OpenAI 发布 GPT-6 Sol 与 Luna](https://openai.com/index/introducing-gpt-6-sol-and-luna/)** — 两款模型把 GPT-6 能力下放到更低价位：Sol 为每百万输入/输出 token 2/10 美元，Luna 为 0.10/0.50 美元，均较 GPT-5.6 对应型号降价 50%；API 模型名分别为 `gpt-6-sol` 与 `gpt-6-luna`。

## 📰 行业动态

### 模型 & 研究

- Claude Opus 5.5 的官方成绩显示：Terminal-Bench 4.0 为 66.4%、FrontierCode 1.1 为 54.4%、CursorBench 4.0 为 57.8%，OSWorld 2.0 为 81.8% partial。Anthropic 同时提醒，前沿模型之间的小幅 benchmark 差距已越来越难映射到真实工作；这些数字仍主要来自厂商评测或早期合作方，需用真实仓库复测。
- Anthropic 报告 Opus 5.5 在一项 HAProxy C→Rust 迁移测试中用 9.5 小时完成，较 Fable 5.1 的 12 小时更快且成本低 51%；另有早期用户完成 68 万行代码迁移。案例有参考价值，但属于官方挑选的早期测试，不应直接外推到普通项目。
- GPT-6 Sol 在 OpenAI 报告的 DeepSWE v1.1 上为 68.8%，Luna 为 66.6%；Sol 在 OSWorld 2.0 offline 为 60.5%。OpenAI 的重点不是争夺绝对最高分，而是把强 Agent 能力压到更低成本；同样需要独立复测，尤其是不同 effort、harness 和缓存命中率下的实际费用。
- OpenAI 为 GPT-6 改进 prompt caching：缓存读取继续享受 90% 折扣，调整 reasoning effort 或启停工具时可保留已有缓存，并增加缓存诊断与显式 breakpoint。这对长会话和频繁工具切换的 Agent，可能比单纯 token 降价更影响总成本。

### 产品 & 工具

- **[Transformers 原生运行 llama.cpp GGUF 量化模型](https://huggingface.co/blog/transformers-llama-cpp-quants)** — Hugging Face 让 `from_pretrained(..., gguf_file=...)` 直接加载 GGUF，并复用 ggml 的 Metal kernels；也可通过 `transformers serve` 暴露 OpenAI-compatible API。初期仅重点支持 Apple Silicon 上的 Qwen3.5/Qwen3.8 dense 与 MoE，packed path 仍是 MPS-only，batching 和架构覆盖尚有限。
- Hugging Face 在 M2 Max 上报告 Transformers 已接近 llama.cpp 的生成吞吐，但两边测试口径不完全一致：Transformers 数字包含 prefill，llama.cpp 使用 decode-only `tg128`。当前更适合把它看成“同一 GGUF 权重进入 PyTorch/Transformers 生态”的便利层，而不是已经替代 llama.cpp 的通用本地推理引擎。

## 🔧 跟我们相关的

- **立刻做一轮三模型成本/可靠性 A/B。** 用 20–30 个真实 OpenClaw 任务对比当前 `gpt-5.6-sol-fast`、`gpt-6-sol` 与 Opus 5.5，统一记录成功率、工具调用错误、恢复次数、输入/输出 token、缓存命中和总价；另用 Luna 跑日报粗筛、分类等低风险任务，验证它是否能替代更贵模型。
- **把缓存命中率纳入 Agent 评测。** OpenAI 允许切换 effort、启停工具而不破坏已有缓存，Anthropic 又把 cache read 降到 0.20 美元/M token；我们的长任务评测不应只看每 token 标价，还要测稳定前缀、工具描述变化和会话恢复对真实账单的影响。
- **抽取 Anthropic 金融仓库的结构，不照搬业务内容。** 重点比较它的 `agent → bundled skills → connectors → managed wrapper` 与 OpenClaw skill/session/tool-policy 的映射，尤其是人工签核、只读/写入边界和 subagent handoff；先做架构卡片，不直接连接付费金融数据源。
- **本地模型实验可用 Transformers + GGUF 降低接入摩擦。** 如果有 Apple Silicon 环境，可用同一 Qwen GGUF 分别跑 llama.cpp 与 Transformers，测首 token、生成吞吐、内存、工具调用正确率和 OpenAI-compatible 服务稳定性；当前不要把 MPS-only 预览路径当生产默认。
