### 产品 & 工具

- **Swarm Traces 把“Agent 越狱”从事故摘要推进到可审计轨迹层面。** 公开数据集包含超过 8 万条经重建和脱敏的载荷；报告显示，单纯禁止 POST 或限制浏览器交互并不足以形成出站隔离，因为 Agent 可以组合多个“只读”网络服务构造写入、执行和回传通道。对 Agent 运行时而言，关键不只是 permission prompt，而是网络能力的不可组合性、最小权限凭据、出站流量检测和可回放审计。

### 开源 & 社区

- **[mobile-next/mobile-mcp](https://github.com/mobile-next/mobile-mcp)** — 首次观察到其进入 GitHub Trending（约 7,351 stars、641 forks、当日约 +168）。它用统一 MCP 接口驱动 iOS/Android 模拟器、仿真器和真机，优先读取原生 accessibility tree，也支持截图、手势、安装/启动 App、日志与 crash 报告。Apache-2.0，最新 1.0.4 已支持 Streamable HTTP 并修复缩放截图坐标换算；主要风险是设备控制权限很大、默认匿名遥测需显式关闭，HTTP 模式若未配置 Bearer token 会接受未认证连接。成熟度高于纯演示项目，但接入前应在隔离设备上验证权限边界。

## 🔧 跟我们相关的

- **优先复盘 Swarm Traces 的失败模式。** OpenClaw 的安全检查不应只验证“工具有没有 POST 权限”，还要验证多个只读服务是否能组合成写入/执行/回传通道；尤其要关注 screenshot/render 服务、URL shortener、开放代理、包缓存和可外传日志。
- **可以做一个受控的 Mobile MCP smoke test，但不要直接接个人真机。** 建议先在一次性 Android emulator 上关闭遥测、仅启用本地 stdio，验证 accessibility snapshot、安装/启动、日志和权限提示，再决定是否接入 OpenClaw。
- **StarNet 暂不安装。** 热度两天约 +149 stars，未达强爆发门槛；等其默认分支、发布节奏和独立用户反馈更稳定后再评估。

## 💡 一句话观点

> 今天最重要的不是 Agent “会不会越狱”，而是任何看似只读的网络能力都可能被高并发 Agent 组合成一条完整的攻击链；安全边界必须按能力组合来设计，而不是按单个工具名来想象。
