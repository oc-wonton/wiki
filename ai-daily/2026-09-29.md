## 🔥 今日头条

- **Anthropic 发布 Claude Sonnet 5.5：同价提速，单任务成本下降** — 新模型相较 Sonnet 5 生成速度提升 30% 以上，标价仍为输入 $2/M、输出 $10/M token；Anthropic 称多数任务因所需 token 更少，单任务成本最高可降 30%。它在 Terminal-Bench 4.0 得分 70.6%，但 10.3% 的 Sonnet 5 对照与巨大跃升主要来自厂商评测，仍应以真实工作负载复测。[官方发布](https://www.anthropic.com/claude-sonnet-5-5)
- **H Company 开源 Holo4 通用计算机操作 Agent 模型** — Holo4 提供 27B dense、35B-A3B MoE 及 Holotron4 Nano，可在 GUI、代码、MCP 与 API 间切换，并公开权重、量化版本、评测轨迹和数据集；官方报告 Holo4-27B 在 OSWorld 2.0 得分 61.7%，低于 Opus 5.5 的 81.8%，但强调更低成本。不同模型的 harness、任务子集和计价方式并不完全一致，结论仍需独立验证。[Hugging Face 发布](https://huggingface.co/blog/Hcompany/holo4)

## 📰 行业动态

### 模型 & 研究

- **Claude Sonnet 5.5 主打“日常任务的效率层”。** Anthropic 将其定位为 Opus 5.5 的低成本补充，适合边界清晰的编码、修复、文档、幻灯片与表格任务。官方数据还包括 FrontierCode 1.1 为 46.2%、OSWorld 2.1 为 80.1%，并称低/中 effort 下可用约十分之一的单任务成本超过 Sonnet 5 的最佳分数。它是首个随 Opus 级网络安全防护与推理抽取防护发布的 Sonnet；高风险网络安全请求可能回退到 Sonnet 5。
- **迁移存在一个具体兼容点。** 在 Claude Platform 上以 thinking off 使用 Sonnet 的调用方，需要切换到新的 `between_tools` 设置后再迁移至 `claude-sonnet-5-5`；Claude App、Claude Code、AWS、Google Cloud 与 Microsoft Azure 均已提供。
- **Holo4 把“同一个模型跨接口工作”作为核心卖点。** 两个主模型可操作桌面、Web、Android、代码沙箱、MCP 和业务 API；项目开放基准轨迹，便于逐步回放。官方也披露 Holo4-27B 的部分长任务成本很高，例如 FreeCAD 示例达到 130 万 token，说明“参数更小”不等于端到端任务一定便宜。
- ArXiv `cs.AI` 最新批次为 9 月 28 日页面更新、论文实际提交集中在 9 月 25 日。可见论文中有关推理效率、多 Agent 扩展和 Coding Agent 文档的研究有启发，但未出现需要压过今日两项模型发布的独立强证据，因此不凑数推送。

## 🔧 跟我们相关的

- **优先做 Sonnet 5.5 的小样本路由评测。** 从真实 OpenClaw 工作中抽 30 个边界清晰任务，与当前默认模型比较成功率、总 token、耗时、重试次数和成本；只有在质量不降的前提下，再把日常任务切过去，复杂开放任务继续保留 Opus/更强模型。
- **把 Jeff 当作“廉价前置路由器”验证，而不是推理 Agent。** 用 200–500 条历史任务测试意图路由、风险分级和是否升级到大模型，同时做提示改写鲁棒性、概率校准与拒答阈值检查。
- **Holo4 先读轨迹再跑模型。** 优先回放其公开 GUI/MCP 轨迹，核对 harness、token 消耗与失败模式；若要本地部署，再从量化版和受限沙箱开始，不直接授予桌面与网络写权限。

## 💡 一句话观点

> 今天的共同信号不是“模型又变大了”，而是把 Agent 分层：便宜模型负责高频执行和路由，强模型负责复杂判断，再用可审计的隔离边界兜住权限风险。
