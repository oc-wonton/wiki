## 🔥 今日头条

- **OpenAI 推出 Dots：把“始终在线的个人 Agent”做成 ChatGPT 正式产品** — 每个 Dot 拥有独立云电脑、长期上下文和 4,000+ 应用插件，可在 ChatGPT、Slack、Teams 中持续工作，并向 Pro、Business Premium 与 Enterprise 逐步开放。它代表 OpenAI 正面进入 OpenClaw 所在的持久 Agent/主动工作赛道，但连接个人电脑、跨应用长期记忆和主动研究也显著放大权限、隐私与提示注入风险。[官方发布](https://openai.com/index/introducing-dots/)
- **OpenAI 发布 GPT-6.1 Sol：以更低价格逼近 Astra 的 Agent 能力** — API 定价为输入 $2/M、缓存输入 $0.10/M、输出 $10/M token；官方称其在 Coding Agent、计算机操作和专业工作上接近 GPT-6 Astra，而标准输入/输出价格仅为 Astra 的五分之一。模型已进入 ChatGPT Work、Codex 与 API，但主要性能结论仍来自厂商基准，需用真实 OpenClaw 工作负载复测。[官方发布](https://openai.com/index/introducing-gpt-6-1-sol/)

## 📰 行业动态

### 模型 & 研究

- **NVIDIA 发布 Kumo Tabular 开放表格基础模型。** 28M–215M 三种规模可在不给模型训练、调参或人工特征工程的情况下，对带标签表格执行分类与回归；代码与权重开放，官方称在 TabArena、BeyondArena、TALENT 和 ScoringBench 四项评测领先。模型只原生处理数值和类别列、单次最多 10 类，训练数据生成器尚未发布，且 SOTA 结论来自 NVIDIA 自测；应用前仍需在自有留出集检查准确率、校准和分布漂移。[Hugging Face 发布](https://huggingface.co/blog/nvidia/kumo-tabular)
- **ProvenanceGuard 把 MCP Agent 的事实核验推进到“来源是否对”。** 新文章介绍一个读取 MCP trace 的后处理层，逐条检查 claim 是否被正确工具来源支持；在 361 条专家标注 claim 中，它抓到 139 条应拦截项里的 138 条，但也误拦了 67 条已获支持的 claim。在相似来源压力测试中，精确识别来源仅 50.3%，说明它适合高风险场景的保守复核，而不是无条件自动放行。[Hugging Face 文章](https://huggingface.co/blog/MultiverseComputingCAI/getting-the-source-right-not-just-the-fact-source)
- ArXiv `cs.AI` 9 月 29 日批次规模很大，但列表页未可靠提取标题，且没有独立强证据足以压过今天的正式产品与模型发布，本期不靠论文标题凑数。

### 产品 & 工具

- **Dots 的权限设计比宣传词更值得看。** 主动研究阶段被代码限制为只读，不能发消息、改应用内容或控制浏览器/桌面；外部写操作需经过独立 Auto-review，永久删除、未知软件安装、扩大敏感权限等操作必须逐次确认。密码可通过独立凭据服务注入而不进入模型上下文。不过 OpenAI 也明确承认 Dots 仍会犯错；断开应用不会自动删除 Agent 已学到的上下文，个人计划的数据训练设置也需要主动检查。[安全说明](https://openai.com/index/how-we-build-safety-security-and-privacy-into-dots/)
- GPT-6.1 Sol 目前在 ChatGPT 中仅进入 Work/Codex，尚未进入普通 Chat；OpenAI 还预告生成速度最高提升 8 倍的 Ultrafast 版本。官方报告其 DeepSWE 1.1 接近 Astra，OSWorld 2.0 与 Astra 相差 2.1 个百分点，低 reasoning 下事实错误率由 Sol 的 11.4% 降至 7.7%；这些评测条件与竞品 fallback 成本口径并不完全一致。

### 开源 & 社区

- **[NVIDIA/OpenShell](https://github.com/NVIDIA/OpenShell)** — 今日首次在 GitHub Trending 观察到的自主 Agent 安全运行时，当前约 10.7k stars、1.4k forks，Apache-2.0，9 月 28 日发布 v0.1.2。它用内核级文件/系统调用/网络策略隔离 Agent，在发出批准请求前以形式化验证分析策略变更，并只在请求发往获批端点时注入真实凭据；支持本地 gateway、Kubernetes、GPU 及 Python/TypeScript/Go/Rust SDK。主要风险是仍处于 0.1.x、安装面和控制面较重、WSL2 仍属实验支持，且默认匿名遥测需显式关闭；适合隔离试验，不宜直接替换现有生产沙箱。
- GitHub Trending 头部的 `debpalash/VoiceStudio`（约 +4,758 stars/日）、`vectorize-io/hindsight`（约 +2,575/日）、`paperclipai/paperclip`（约 +2,458/日）、`mvschwarz/openrig` 与 `dream-num/univer` 均已有推送记录，不因连续上榜重复报道。与这些已验证有持续社区信号的成熟候选相比，OpenShell 虽有 NVIDIA 背书和完整发行链，但版本成熟度更低；本期因首次观察、近期正式 release 与对 OpenClaw 安全边界的高度相关性保留新项目席位。

## 🔧 跟我们相关的

- **优先做 GPT-6.1 Sol 路由 A/B。** 用 30–50 个真实 OpenClaw 编码、网页操作和文档任务，与当前默认模型比较成功率、总 token、耗时、重试和单任务成本；不要直接依据厂商 benchmark 全量迁移。
- **拆解 Dots，而不是模仿“24/7”口号。** 对照 OpenClaw 现有能力逐项检查：主动研究必须只读、外部写操作独立复核、密码不进模型上下文、Agent 上下文可重置、敏感权限逐次确认。真正可复用的是权限与审计结构。
- **在隔离环境评测 OpenShell。** 先验证文件/网络 deny-by-default、端点绑定凭据、策略差异审阅和遥测关闭，再考虑它是否能补强现有 Cloud Worker/沙箱；暂不在生产主机执行一键安装。
- **把来源归属纳入 Agent 结果验收。** 对多工具研究任务，不只保存最终引用，还保留 claim → tool output/source ID 映射；ProvenanceGuard 的高误拦率说明它更适合作为“需要复核”的信号，而非单独裁决器。
