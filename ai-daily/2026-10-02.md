## 🔥 今日头条

- **Cloudflare 发布 Clef / Clef-flash：把 Agent 的高频判断从通用 LLM 拆成开放权重决策模型。** 两款模型直接输出带概率的有界结构化结果，兼容 Jev API；Clef 支持图像与 64K 上下文，权重以 Apache 2.0 发布，Cloudflare 同时上线 Workers AI 托管版并预告基于真实业务数据的 RL 微调服务。官方称 Clef-flash 在其评测中位延迟约 38.8ms、p95 约 122.4ms，但榜单、延迟和企业案例主要由 Cloudflare 自测，仍需用真实路由数据验证校准误差与失败升级率。[Cloudflare 官方发布](https://blog.cloudflare.com/clef-decision-models/)
- **Pi 1.0 正式发布，并把“可恢复的长期 Agent”拆成实验性 Pi Durable。** 1.0 为成熟 coding-agent harness 增加 Codemode、MCP/非 LLM 模型、虚拟模型、延迟加载工具、Anthropic cache warming 和会话中系统消息；Pi Durable 则提供 SQLite/JSONL 存储、任务检查点、崩溃恢复、并发/分叉对话、exactly-once submission 以及可声明是否安全重放的工具。发布后 Hacker News 约 711 points / 245 comments；但 Pi 本身默认继承启动进程权限、没有内置权限系统，Durable 仍明确标为实验性。[Pi 1.0 公告](https://earendil.com/posts/pi-1-0/)

## 📰 行业动态

### 模型 & 研究

- **Allen Institute 发布 Olmo-core 3，开放面向万亿参数 MoE 的训练基础设施。** 新栈以 DDP、expert/pipeline parallelism、分布式 optimizer、GPU-resident routing、grouped GEMM 和 MXFP8 重做 MoE 训练路径。官方在 8 张 B300 上报告 47B MoE 从旧栈的 19.4K 提升到 52K tokens/s/GPU；四张 B300 上 MXFP8 相比 BF16 吞吐约 +21%、峰值显存从 103 GiB 降到 95 GiB。1.2T 参数测试使用 512 张 B300，2.38T 只做短时 capacity test，且部分测试采用随机路由，只能证明系统可扩展性，不能证明训练后的模型质量。[Hugging Face / Ai2 文章](https://huggingface.co/blog/allenai/olmocore3)
- **Clef 的价值是“概率决策层”，不是更小的聊天模型。** Cloudflare 冻结 Qwen3.8-27B / Qwen3.5-9B 主干，用 LoRA、schema-bound scoring 与校准损失直接给选项打分；这更适合工单路由、工具选择、风险分级等有有限动作空间的热路径。官方 43 项评测并非全面碾压：Jev 在 When2Call、BRIGHT 与部分 Agent trace 评测仍领先，说明真实收益依赖任务分布。
- ArXiv `cs.AI` 10 月 1 日批次共有 394 条，列表页仍未可靠提取标题；本期没有用无法核验的论文标题凑数。

### 产品 & 工具

- **Pi 1.0 把模型路由变成一等扩展能力。** 虚拟模型可让一个模型规划、另一个模型执行，再由 Jev 等决策模型判断切换时机；Deferred tool loading 和 prompt/tool 中途更新则减少长期会话的上下文负担。这与 Clef 的发布形成清晰趋势：Agent harness 正把“生成”“决策”“工具执行”拆成不同模型与运行时层。
- **Pi Durable 的恢复语义值得关注。** 每个模型请求、工具调用和 compaction 都是带检查点的 task；崩溃后，安全工具可重放，非幂等工具只向模型报告中断，`requestId` 防止客户端重试重复提交。它可用内存、SQLite 或 JSONL 后端，也允许同一 harness 运行并分叉多条对话；但只有单进程拥有一个 storage，且官方仍将该包定义为实验性，暂不宜替代成熟生产调度器。[Pi Durable 设计说明](https://earendil.com/posts/pi-durable/)

## 🔧 跟我们相关的

- **给 OpenClaw 路由层做一次 Clef-flash 隔离评测。** 从真实历史任务抽取“是否需要工具、选哪个 provider/model、是否升级人工、是否允许后台执行”等有限选择题，比较 Clef-flash、现有规则和小型通用模型的校准误差、p95 延迟、成本与错误升级率；达不到可解释阈值就不进生产热路径。
- **借鉴 Pi Durable 的工具重放契约。** 给关键 OpenClaw 工具明确标注只读可重试、带幂等键可重试、禁止自动重试三类，并让 task checkpoint 在执行前持久化意图；这比“进程重启后让模型猜刚才发生了什么”可靠。
- **不要直接在宿主机试跑 Pi 1.0。** 若做对照实验，使用临时容器或 OpenShell，禁用真实凭据和写权限，重点验证 Codemode、延迟工具加载、mid-conversation tool changes 以及模型路由，而不是重复评估它已有的基本 coding-agent 能力。
- **Olmo-core 3 先当训练系统参考，不当模型选型新闻。** 它开放的是 MoE 基础设施与消融经验，不是可直接接入 OpenClaw 的新推理模型；仅在研究训练/微调基础设施时深入跟进。

## 💡 一句话观点

> Agent 栈正在分层：大模型负责开放式生成，小决策模型负责高频路由，durable runtime 负责把每一步变成可恢复、可审计、可安全重放的状态机。
