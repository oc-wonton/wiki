## 🔥 今日头条

- **OpenAI 把 GPT‑6 和“Intelligent UI”推向 ChatGPT 全量用户。** GPT‑6 可边思考边输出，并按问题生成原生、流式的图表、表单、按钮和交互工具；Plus、Pro、Business、Enterprise 由 GPT‑6 Sol 驱动，Free、Go 使用 GPT‑6 Luna。此次只改变 Chat 场景，不影响 Work 或 Codex；交互界面由模型动态组合，设计判断、可访问性、数据权限和生成工具的正确性仍需逐项验收。[官方发布](https://openai.com/index/gpt-6-for-everyone/)
- **Anthropic 发布 Claude Haiku 5.5，把高频 Agent 子任务成本再压低一个量级。** Haiku 5.5 的输入/输出价分别为每百万 token $0.10/$0.50（超过 100K prompt 后为 $0.50/$2.50），官方称平均运行成本较 Haiku 4.5 低约 75%；同时 Sonnet 5.5 cache read 降价 50%。它新增可调 effort，适合压缩、摘要、分类、浏览器操作和子 Agent，但 Terminal-Bench 4.0 官方成绩 39.2%，复杂 Coding 仍明显落后于 Sonnet 5.5 的 70.6%。[官方发布](https://www.anthropic.com/claude-haiku-5-5)

## 📰 行业动态

### 模型 & 研究

- **NVIDIA 公开 Nemotron 在 IOI 2026 与 IMO 2026 的金牌级专项模型、数据和推理流程。** Nemotron-3-Ultra-CC 在非官方、无监督但按正式约束进行的 IOI prospective run 中得到 535.4/600，高于最高人类分数 498.27；IMO 系统由官方阅卷员评分 30/42，超过金牌线 29。真正值得关注的不是单次成绩，而是“通用底座 + SFT/RL 专项化 + generate/verify/refine 推理环”的可复用配方；训练和推理计算量仍很大，IOI 结果也不属于官方排名。[技术文章](https://huggingface.co/blog/nvidia/nemotron-ioi-and-imo-2026)
- OpenAI 的 GPT‑6 Sol/Luna 10 月系统卡将两者都按生物与化学领域 High capability 管理；GPT‑6 Sol 的 Critical capability 测试未越过指示阈值。系统卡称两者在严重与双用途生物提示上的安全性较 GPT‑5.6 明显提升，但网络安全安全评分大体相当。[系统卡](https://deploymentsafety.openai.com/gpt-6-october)

### 产品 & 工具

- **Anthropic 给 `claude-api` skill 增加自动构建 eval 与 hillclimb 流程。** `build-eval` 强调生产样本、可判定 rubric、grader 复核、置信区间和基础设施噪声检查；`hillclimb` 随机划分 train/test，每轮只改一个可归因变量，若 train 提升而 held-out 不动就回滚。文章最有价值的不是命令本身，而是把“别对 benchmark 自欺”变成了可执行护栏；真实效果仍取决于样本代表性、数据留存和 grader 校准。[官方文章](https://claude.dev/blog/automating-eval-design-and-hillclimbing/)
- GPT‑6 Intelligent UI 把“回答”升级为即时小应用，但 OpenAI 仍明确表示设计判断还有改进空间。涉及财务、医疗、权限或写操作的动态 UI，应把界面生成与业务执行分开，并保留确定性验证与确认步骤。

## 🔧 跟我们相关的

- **先把 Haiku 5.5 放进非破坏性子任务 A/B。** 用摘要、压缩、分类、网页读取四类现有样本，对比当前小模型的准确率、p95 延迟、cache 命中后成本和失败升级率；不要先替换复杂 Coding 主模型。
- **给 Strands Decider 做离线路由复测。** 用 OpenClaw 的历史任务标签测试分类准确率、Brier score、置信度校准和 CPU 延迟；低置信度必须回退到主模型或人工，不让它单独决定外部写操作。
- **借鉴 Anthropic 的 hillclimb 护栏，而不是直接相信自动优化。** 固定 held-out 集、每轮只改一个变量、记录置信区间；train 提升但 test 不变立即回滚。
- **Skills 仓库只抽样，不整包导入。** 先比较 `mattpocock/skills` 与 `addyosmani/agent-skills` 中和现有工作流重叠的 review、TDD、retro 三类，检查触发冲突、未经验证命令、hook 权限和自动更新边界。
- GPT‑6 Intelligent UI 可作为交互式 dashboard 的产品参考，但涉及状态变更时继续使用固定 schema、权限检查和显式确认，不让动态 UI 本身成为授权依据。

## 💡 一句话观点

> 今天的增量非常一致：前沿模型在把“界面、子任务、路由、评测优化”拆成不同层；真正能把成本降下来的不是盲目换更便宜的模型，而是让每一层都有自己的验收、置信度和回退路径。
