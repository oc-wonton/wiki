## 🔥 今日头条

- **Anthropic 用五个月把近 100GB 主干历史迁出 Git，公开面向 Agent 规模的 Scion 源码管理架构。** Anthropic 称内部日合并量从 2026 年 5 月约 2,500 次升至 9 月超过 30,000 次，CI 每天约 2,500 万次 checkout；七人团队构建 Scion 与代码审查面 Antique，并把 CI/研究任务 checkout 从分钟级降到秒级、基础设施 CPU/内存缩小约 200 倍、CI CPU 容量节省 25%。这不是可直接采用的开源产品，而是一份很清楚的信号：当 Coding Agent 让“写代码”不再稀缺，版本控制、review、CI 和权限模型会先成为瓶颈。[Anthropic Engineering](https://www.anthropic.com/engineering/redesigning-source-control)

### 产品 & 工具

- **Uber 把 Agent 安全明确类比为“内部威胁治理”，并公开生产系统 ADR。** Uber CISO 表示，Agent 需要像员工一样接受实时检测、越权干预和行为趋势分析；开源 ADR 已在 Uber 生产使用，覆盖 AI 工具发现、Claude Code/Cursor/Codex 等 7+ harness 的遥测、304 个任务与 134 个 MCP server 的安全基准，以及双层威胁检测。需要注意：开源版不含阻断组件和离线 ADR Explorer；遥测会接触意图、工具调用与执行轨迹，部署前必须先确定数据最小化、保留期限和访问审计。[Claude 访谈](https://claude.com/resources/articles/uber-s-ciso-on-building-an-insider-threat-program-for-ai) · [uber/ADR](https://github.com/uber/ADR)
- **Scion 的关键不是“Git 已死”，而是为永远在线的 Agent 放弃离线完整副本。** 客户端只维护有界缓存，merge/rebase/commit 在服务端完成，稀疏与虚拟 checkout 成为默认；这适合 Anthropic 的极端单体仓库和在线 Agent，但也换来了中央服务依赖、离线能力下降和更复杂的服务端权限边界。普通团队无需复制架构，先量化 checkout、merge queue、review 和 CI 的真实瓶颈。

## 🔧 跟我们相关的

- **优先做 LFM2.5-24B-A2B 的本地路由 Spike。** 选 20 个真实但无敏感数据的 OpenClaw 工具任务，固定硬件与量化版本，对比当前本地模型的成功率、工具参数错误、首 token/总延迟、峰值内存和每任务能耗；同时封闭 Git 历史和公开答案，防止评测泄漏。
- **把 ADR 当“安全可观测性参考”，不要直接全量采集。** 先只记录工具名、结果状态、风险标签和匿名化资源类别；禁止默认保存 prompt、文件内容、凭据、完整命令输出。只有在保留期限、访问权限、删除路径和误报处置都明确后，才考虑更细粒度轨迹。
- **为 Coding Agent 建一个“基础设施饱和度”看板。** 追踪 checkout 时长、merge queue 等待、CI fan-out、review backlog、冲突率和 Agent 重试；只有这些指标持续成为瓶颈时，才评估稀疏 checkout、服务端 diff 或专用版本控制，不要照搬 Scion。
- **ArtCraft 只评测工作流，不上传私人素材。** 先核验 Windows/macOS 安装包签名、模型供应商与数据条款、缓存/删除路径和项目文件可移植性，再用公开素材测试 2D/3D 构图是否真的比现有图像工具稳定。

## 💡 一句话观点

> Agent 把软件团队的瓶颈从“谁来写代码”推向“谁来管版本、权限、遥测和基础设施”；本地高效模型解决的是成本，Scion 与 ADR 暴露的才是规模化之后真正难的系统问题。
