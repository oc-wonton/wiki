## 🔥 今日头条

- **Claude 解开了 NIST 椭圆曲线种子来源的 25 年谜题。** Anthropic 团队让内部研究模型从生成软件的历史约束反推，发现 P-192、P-224、P-256、P-384、P-521 等曲线种子并非口令哈希，而是 1990 年代 C 库 `lrand48` 以 Unix 时间戳初始化后的输出；文章附可复现代码。这个结果不是 ECDSA 漏洞，反而降低了“参数被秘密挑选植入后门”的疑虑，但 B-163 和数个基点来源仍未解释。Hacker News 约 647 points / 263 comments，说明密码学社区高度关注。[Anthropic Research](https://www.anthropic.com/research/ecdsa-curve-origins)
- **Reflection 正式开放 501B 参数 Agent/Coding 模型 Beam。** Beam 是 501B 总参数、23B 激活的文本 MoE，提供 100 万 token 上下文、结构化 tool calling、可保留跨轮 reasoning、BF16/FP8/NVFP4 权重和 Rust harness，并以 Apache-2.0 发布；Transformers、vLLM、SGLang 首日支持。相对 10 月 6 日仅有预告，本次新增了真实权重、推理/训练配方和公开 trace，因此属于独立增量。代价也很现实：BF16 约 1 TB，NVFP4 仍约 280 GB，官方建议至少 4×B200；主要 benchmark 来自项目方，独立复现尚少。[Hugging Face 技术发布](https://huggingface.co/blog/reflection-beam)

### 产品 & 工具

- **Anthropic 公开 Claude Code 团队的分层代码审查流程。** 其内部流程把验证、fresh-context subagent review、PR bug review、安全 review、CI、按风险分级的人审、merge queue、灰度和回滚串成多层防线；6–9 月合并 PR 数量翻倍以上，同时 revert 占比下降 40% 以上。最值得借鉴的不是“90% 代码由 Claude 写”，而是每个结论必须附可运行证据、低/中/高风险对应 0/1/2 名人审、机器人审批永不替代必需的人审、review 最多三轮后重新评估方案，并把事故与回滚持续转成 eval。[Claude Developer Blog](https://claude.dev/blog/solving-code-review-at-anthropic/)

## 🔧 跟我们相关的

- **把 Anthropic 的 review 分层直接映射到 Agent 编码流程。** 最小改动是：实现 agent 必须给出测试/构建/截图证据；独立 reviewer 只看 diff、目标和仓库规则；敏感路径强制真人；三轮 review 不收敛就暂停补丁式修修补补，重新判断方案；每次事故进入回归 eval。
- **Beam 先做 API 级盲测，不做自托管。** 选 10 个真实 OpenClaw 工具调用、长上下文和 coding 任务，与当前稳定模型比较成功率、工具参数正确率、token、延迟和成本；除非有多卡 Blackwell 预算，否则不为“开放权重”承担 280 GB 以上权重常驻成本。
- **将 benchmark coverage 纳入采用评审。** 每次声称模型适合某业务前，先列真实任务分布、失败成本和 benchmark 未覆盖区域，再用内部 golden set 补齐；避免把单一软件工程榜单外推到全部 Agent 场景。
- **密码学结论只做知识更新，不做配置变更。** ECDSA 研究明确不是漏洞或迁移通知；不要因为标题含“curve origins”就轮换密钥或更换曲线，除非相关标准机构另有正式安全公告。
