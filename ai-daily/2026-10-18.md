## 🔥 今日头条

- **OpenCode 披露安全事件，部分 Console 用户的模型供应商凭据可能暴露。** OpenCode 官方称，一个正在下线的旧系统遭未授权访问，影响约 1.4% 的 OpenCode Console 用户；其通知邮件要求受影响者撤销并替换保存在 workspace 中的 OpenAI、Anthropic 等第三方 provider keys，并检查异常用量。官方把事件与“大规模蒸馏攻击”联系起来，但截至本期仍未发布完整时间线、攻击路径或取证报告。Hacker News 约 742 points / 126 comments，讨论重点集中在云端 BYOK 的信任边界。若使用过 OpenCode Console/Zen 并保存过 provider key，应立即轮换，而不是等待完整复盘。[OpenCode 官方公告](https://x.com/opencode/status/2111516673953935833)
- **DeepSeek 发布 DeepSeek-V4.1-Flash-1017，并开放 Search / Fetch API。** 这是 V4.1-Flash 的小版本更新，官方称在 reasoning、coding、Agent 和视觉任务上同时改善，并减少执行时间与输出长度；模型权重与代码采用 MIT，支持 100 万 token 上下文、最高至少 256K 输出，并发布 `deepseek-recipe` 处理 Messages、Chat Completions、Responses API、工具调用和多模态 prompt 编解码。Search / Fetch 每个 endpoint 定价为每千次 0.75 美元，DeepSeek API 用户通过 DeepSeek Harness、Claude Code、Codex 的服务端工具调用暂时免费至 10 月 31 日 16:00 UTC。benchmark 主要来自官方，仍需独立复现。[DeepSeek 官方发布](https://api-docs.deepseek.com/news/news261017/)

## 📰 行业动态

### 模型 & 研究

- **DeepSeek-V4.1-Flash-1017 的真实增量是“更短、更快的 Agent 执行”，而不只是榜单上涨。** 官方报告 Terminal-Bench 4.0 从 31.2 提升到 42.3、DeepSWE v1.1 从 74.2 到 77.0、Automation-Bench 从 54.8 到 60.5；这些均为项目方测试，且不同模型的 harness 与采样条件未必完全一致。值得验证的是同一真实任务下的完成率、工具参数正确率、输出 token 与总成本，而不是跨模型单点排名。
- ArXiv `cs.AI` 最新仍为 10 月 16 日批次（首屏显示 286 条）；本期没有仅凭标题硬凑论文。Anthropic News、Anthropic Engineering 与 Claude Blog 均完成检查，未发现相对昨日账本的新官方卡片。

### 产品 & 工具

- **OpenCode 事件再次暴露“本地开源客户端 + 云端 Console/BYOK”容易被误解为同一安全边界。** 本次公开信息指向旧云端系统和保存在 workspace 的 provider keys，不等于已证明纯本地 CLI 本身泄露凭据；但在完整复盘出来前，任何把第三方 key 交给 Console 的用户都应按已暴露处理。官方尚未给出受影响时段、日志保留、密钥加密方式和攻击者访问范围，这些是后续采用判断的关键。
- **llmspeed 提供“买硬件前先感受本地模型速度”的交互式估算。** 网站按 GPU/Mac/CPU 和模型浏览，用动画还原预估 token 速度；项目明确区分社区实测与基于相似配置/规格推算的数据。它适合做采购前的第一轮筛选，不适合替代本机 benchmark。[llmspeed](https://llmspeed.dev/)

## 💡 一句话观点

> 今天的共同主题是“控制面才是风险集中地”：模型更强、Agent 更多并不自动带来可靠性，凭据托管、远程执行、技能安装和性能估算都必须有可撤销、可验证、最小权限的边界。
