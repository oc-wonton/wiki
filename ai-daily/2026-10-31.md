## 🔥 今日头条

- **Cursor 扩展市场出现被植入持久 SSH 后门的伪造 Claude Code 扩展。** Cursor 确认 `Anthropic.claude-code` 2.1.312 与 2.1.313 的 macOS/Windows 包在 10 月 29 日约 02:27–13:35 PT 被恶意修改；载荷会收集主机信息、向 `authorized_keys` 写入攻击者密钥、尝试启用 SSH 并建立反向隧道和开机持久化。Cursor 已下架版本、关闭并重建市场、轮换密钥、下线攻击服务器，但卸载扩展不足以清除独立持久化脚本。凡在该时段从 Cursor Marketplace 安装或更新过这两个版本的机器，都应按官方 IOC 检查、隔离命中主机，并从可信设备轮换可访问的凭据与会话。[Cursor 官方安全通告](https://cursor.com/blog/claude-code-extension-security-notice)
- **OpenAI 将支持跨厂商统一的 `robots.txt` AI 训练偏好信号。** 网站不必再逐个维护各家的训练爬虫规则，即可表达内容是否可用于基础生成式 AI 训练；OpenAI 表示将在未来数月实现，同时继续尊重现有 crawler controls。方向很重要，但当前仍是自愿标准与实现承诺，不能误当作已经生效、也不覆盖搜索索引或推理时抓取等所有用途。[OpenAI](https://openai.com/index/helping-websites-express-ai-training-preferences/)

### 开源 & 社区

- **`thedotmack/claude-mem` 发布 v15.7.0，修复一次会偷偷消耗其他 Agent 额度的回退行为。** 当 My Work 自动刷新结果被拒收时，旧逻辑会切到下一位已登录 Agent；作者记录到有 Codex 的机器即使设置 `CLAUDE_MEM_PROVIDER=claude`，仍在四天内触发约 230 次隐藏的 `codex exec --ephemeral`。新版让“结果被拒收”停留在原 Agent，仅真正无法运行时才回退；同时修复嵌套项目记忆泄漏、跨源浏览器写入、Postgres API key 哈希、凭据脱敏、原子写入等问题，并加入 OMP/Claude Duet 支持。仓库现约 106,262 stars / 9,354 forks、今日 Trending +1,140；升级价值高，但自动捕获、后台 worker、数据库和多 Provider 访问面仍需先在副本验证。[Release](https://github.com/thedotmack/claude-mem/releases/tag/v15.7.0)
- **新锐项目 `dbreunig/nesformer` 把 NES 6502 CPU 编译进标准 Qwen3.5 checkpoint 的权重。** 它没有训练模型，而是计算出约 466.6M 参数（约 9.3M 非零）的电路权重，并借 Gated DeltaNet state 保存寄存器、RAM 和 ROM；作者报告打包测试游戏的 token trace 与参考模拟器一致。项目上线不足一天约 150 stars / 6 forks，但 HN 已有约 183 points / 110 comments，属于“讨论信号强、规模证据仍早期”的新锐席位。局限也很明确：仅支持 NROM、无声音、PPU 在 host、速度比真机慢 150–290 倍，验证主要来自作者自测，适合作为“Transformer 状态可充当可编程计算机”的研究样例，不是实用模拟器。[GitHub](https://github.com/dbreunig/nesformer)

## 🔧 跟我们相关的

- **先排查 Cursor Marketplace 暴露面。** 如果任何 macOS/Windows 开发机在 10 月 29 日对应时段安装过 Claude Code 2.1.312/2.1.313，不要只卸载扩展；按 Cursor 官方脚本与 IOC 检查 `svc-telemetry` SSH key、隐藏脚本、LaunchAgent/计划任务和隧道进程，命中后隔离并从可信设备轮换凭据。
- **把扩展/skill 安装源纳入供应链控制。** 对高权限 Agent 工具优先使用官方发布渠道和可验证 hash；自动更新前保留版本、来源与安装时间，扩展 host 对 `~/.ssh`、shell rc、凭据目录和持久化机制的写入应单独告警。
- **claude-mem v15.7.0 的教训适用于 OpenClaw 多 Provider 调度。** “输出不合格”和“Provider 无法运行”必须是不同状态，前者不能静默回退到另一个付费或高权限 Agent；应在账单、任务日志和 UI 中显式记录实际执行 Provider。
- **nesformer 只值得读实现，不值得部署。** 重点看 DeltaNet state 如何承担可寻址内存、如何把确定性电路编译成 checkpoint，以及作者如何与参考 CPU 做 trace 对照；不要把一次作者自测的演示外推为通用推理能力。

## 💡 一句话观点

> 今天最重要的不是新模型，而是两条边界同时被拉清：Agent 扩展拥有开发机级权限，供应链失守会直接变成持久后门；多 Agent 的“自动回退”若不透明，也会悄悄越过费用与权限边界。
