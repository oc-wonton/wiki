## 📰 行业动态

### 模型 & 研究

- **CWE-bench v2 开放 100 个真实仓库安全修复任务，覆盖 91 类 CWE。** 每个任务给 Agent 一个真实开源仓库和简短修复指令，用确定性 verifier 检查漏洞是否修复、原功能是否保留，并专门测试记忆上游补丁的解法是否会失败；另有 held-out 集维持污染外评测。项目方报告 11 个模型中 Gemini 4 Argon 为 67.8% pass@1 / 81.0% pass@4，Claude Opus 5.5 为 67.3% / 78.0%，仍有 19% 任务没有任何一次被领先模型解出。公开集、grader 和 Harbor harness 可复现，但榜单仍由 benchmark 维护方设计和运行，不能单独代表真实生产安全能力。[Hugging Face](https://huggingface.co/blog/cwe-bench)
- **权重空间实验的增量价值主要落在“可审计的模型辅助分析”，不是超人式直读权重。** Honnibal 的实验拆分显示：小网络 raw-float 识别、写小型游戏网络、对大模型做代码辅助分析和局部修改，是三类不同能力，不应合并成单一突破；Qwen 本地复现实验说明前一类能力并非 GPT-6 Astra 独有，但耗时 46–65 分钟、4 个游戏失败 1 个，远未证明通用性。
- ArXiv `cs.AI` 更新至 11 月 3 日批次，共 521 条；本次没有发现同时具备强外部讨论、开放实现和直接采用价值、且优于上述可复查结果的新论文，不以摘要列表凑数。

### 产品 & 工具

- **Postman 事件暴露的是 Agent 生态的控制面风险，而非普通插件体验问题。** 报告中的安装逻辑跨越了应用边界：修改两个 coding agent 的全局配置、注册远程 MCP、加入会话启动指令，并尝试写入 hook 信任记录。即便最终确认没有数据外传，默认安装、默认路由和自我批准也违反最小权限与用户可归因原则。采用结论应等待 Postman 官方回应、干净环境复现和完整卸载说明，但现阶段应先审计本机插件目录与启动 hook。

## 🔧 跟我们相关的

- **立即审计 Agent host 的“外来控制面”。** 检查 Codex/Claude Code/OpenClaw 的用户级 marketplace、plugin、MCP、session-start hook 和 trusted-hash 记录；任何跨应用安装必须拆成可见、可拒绝、可回滚的逐项同意，插件不能批准自己的 hook。
- **把 CWE-bench v2 纳入安全 Agent 验收候选。** 先选 5–10 个与当前代码栈相关的任务，在固定容器、禁用生产凭据和限制出站网络条件下验证 pass@k、误修复、原功能保持和成本，再决定是否扩大。
- **用 `worktrunk` 只做隔离层小试，不启用自动 merge。** 先验证 worktree 路径、依赖缓存污染、hook 执行、端口分配和清理回滚；Agent 提交与合并仍保留人工检查。
- **修正昨日对权重空间编程的内部判断。** 将其标记为“值得复现的模型辅助 ML 工程实验”，而不是“模型已能通用理解和直接编程大模型权重”；任何采用结论都需要跨模型、跨随机种子、无工具/有工具分层和安全行为回归。
