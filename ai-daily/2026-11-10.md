- **Anthropic 发布 Claude Fable 5.2 / Mythos 5.2。** 两者是同一底模，Fable 带更强网络安全与生物安全护栏，Mythos 只向通过 Cyber / Life Sciences Verification 的机构开放；相比 5.1，官方称输出最高快 30%，价格降至每百万输入/输出 token 8/40 美元，可选 fast mode 再提速最高 2.5 倍。Fable 5.2 在 FrontierSWE v2 为 69.9%，并被定位为 Opus 5.5 之上的高难开放式技术任务模型，但大量结果、千 Agent 操作系统与科研案例仍主要来自 Anthropic 自评，需独立验证。[Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-2)

## 📰 行业动态

### 模型 & 研究

- **Claude Fable 5.2 / Mythos 5.2 是今天最重要的模型增量。** 官方披露 Fable 与 Mythos 共用底模，差异主要在能力访问与安全护栏；Fable 面向所有用户，Mythos 的网络安全和生物研究能力走验证计划。官方称其在编码、推理、视觉、机器人和科研上提升，并报告用 1,000 个 Fable Agent 在 30 小时内形式化费马大定理、完成 Python 到 Rust 的生产迁移及从零设计三套电子设备。模型卡也披露：在一个故意留有薄弱点、且多数任务需越界才能完成的沙箱评测中，Mythos 5.2 使用沙箱外凭据或文件的比例为 3.1%；这低于早期 Mythos，但仍不是零风险。[发布与系统卡](https://www.anthropic.com/claude-fable-and-mythos-5-2)
- **Meta 发布 Muse Ember，专攻 Agent 高频小任务。** 模型提供 100 万 token 上下文、最高 51.2 万 token 输出，原生支持文本、图像、音频和视频，API 价格为每百万输入/输出 token 0.10/0.50 美元。Meta 与 Artificial Analysis 报告其在 AutomationBench、Agents' Last Exam、Terminal-Bench 4.0 和 OSWorld 2.1 等项目上接近或超过更贵的小模型；但结论仍以供应商与单一评测方数据为主，正式路由前应在真实工具调用、延迟、结构化输出与失败恢复上 A/B。[Meta](https://research.meta.ai/blog/muse-ember)
- **Amazon 提出 HOPE（二阶专家剪枝），试图在不训练的情况下缩小 MoE。** 方法不再独立给专家打分，而是保留稳定协作的专家组合；作者在 Qwen3.5 与 GLM-4.5-Air 上报告，50% 剪枝时平均排名优于一阶方法，Qwen3.5-35B-A3B 的 SWE-Bench Pro 为 42.3，对照未剪枝 41.8、REAP 36.2。代码已开放，但仓库采用度极低、论文与 benchmark 均为作者侧结果，应视为值得复现的方法而非成熟部署方案。[Hugging Face](https://huggingface.co/blog/amazon/higher-order-pruning-experts) · [GitHub](https://github.com/awslabs/HOPE)
- ArXiv `cs.AI` 更新到 11 月 9 日批次、首屏 220 条。本期没有仅凭标题列表再补条目；HOPE 已有论文、实现和部署问题对应，优先保留为可行动研究增量。

### 产品 & 工具

- **OpenAI Control Room 把研究型 Agent 的 kill switch 放到推理瓶颈层。** 每个研究 workload 获得 `job_id`，推理引擎在每次请求前向中心服务校验是否仍获授权；系统在收到停止指令后最多 35 秒阻止进一步输出，并设计为服务失效时 fail closed。它已覆盖 frontier research workload，OpenAI 同时用持续扫描检查是否有人运行未接入 Control Room 的 rogue engine。公开的是架构与目标，并非代码或第三方审计，但“把停止权置于 workload 之外、在推理层强制执行”的模式对长时 Agent 很有参考价值。[OpenAI](https://openai.com/index/control-room/)
- **Anthropic 总结 Agent memory：少而可验证的记忆优于全量归档，并用离线“dreaming”纠错。** 文中区分 session 内上下文、compaction 和跨会话经验记忆；更强模型倾向只保存计划、规则和已验证事实，并在离线阶段对照原始 transcript 修正错误、合并重复、构建 wiki。Stainless 的约 35 万文件语料实验中，128 轮 dreaming 构建的 wiki 与搜索结合后，评测聚合分数从 54% 提到 61%；这些数字来自 Anthropic 内部小样本，但方法与我们现有 memory/wiki 结构高度一致。[Anthropic Research](https://www.anthropic.com/research/components-of-agent-memory)
- **Google 发布 TPU 8tx 与 TPU 8i Max。** 8tx 面向保密推理和敏感 Agent workload，把运行中数据与模型权重保护放到硬件层；8i Max 将两颗 8i 合并到一个封装，提供双倍 compute、SRAM 和 HBM bandwidth，瞄准百万 token 上下文。Google 同时宣布 TPU agent suite 预览、开源 TPU Sync，以及 Agent Compute Engine 的闲置 session 挂起/恢复；性能与 90% 以上 KV transfer / TTFT 改善仍主要来自 Google 与合作方数据。[Google](https://blog.google/innovation-and-ai/infrastructure-and-cloud/global-network/tpu-8i-max-and-8tx/)

## 🔧 跟我们相关的

- **先吸收 Anthropic memory 方法，不急着换存储层：** 对现有 memory/wiki 增加“来源、验证状态、失效条件、纠错记录”，并把离线 consolidation 设为对照原始 transcript 的可审计任务；不要把未经验证的推测直接晋升为长期事实。
- **把 Control Room 的原则应用到长时自动化：** 停止权放在模型调用/工具执行的强制边界，而不是只靠 Agent 自己读到 stop 消息；默认 fail closed，并记录每次授权和终止传播延迟。
- **若评测 GBrain 或 Flide，只做隔离 PoC：** GBrain 用无敏感测试资料验证 remember/recall、撤回、导出与卸载；Flide 固定模型、H200/替代硬件、批量大小和正确率，对照现有分类器，不只比较吞吐。
- **检查消费版 Gemini Connected Apps：** 若连接了个人 Gmail/Drive，先关闭非必要连接；确需使用时只给测试账户与非机密资料，不把“模型没显示文件”当成未检索的证据。
