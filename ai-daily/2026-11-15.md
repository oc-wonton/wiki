## 🔥 今日头条

- **[Google 用 Antigravity `/teamwork` 把多 Agent 推向可验证科研](https://research.google/blog/advancing-science-engineering-with-antigravitys-teamwork-feature/)** — Google 把并行探索、独立 critic/auditor、Lean 4、测试套件、模拟器和硬件计数器组合成长期研究工作流，并宣布相关模式已进入 Antigravity。官方列出的结果包括 Courtade–Kumar 猜想的完整证明与 Lean 形式化，以及多项算法、形式验证和系统优化；这是“生成很多候选”走向“由外部判据淘汰错误候选”的重要工程范式。但成果来自 Google 与合作团队披露，规模、成本和外部可复现性仍需逐项核验。
- **[Lovable 应用被发现大规模暴露敏感数据](https://www.crissyfield.de/research/lovable-en/)** — Crissy Field 基于 Common Crawl 分析 159,041 个 Lovable 项目，其中 34,545 个使用 Supabase；在进一步检查的 24,664 个站点中，7,403 个站点的 10,560 张表含邮箱记录，还发现护照信息、20 多万条私聊、合同与内部邮件摘要。研究者明确提醒样本不代表全部应用，邮箱也不等于确认泄漏率，但案例足以说明：vibe coding 不能替代行级权限、租户隔离和上线前安全审计。

## 📰 行业动态

### 模型 & 研究

- **[Antigravity `/teamwork` 公布长程科研与工程结果](https://research.google/blog/advancing-science-engineering-with-antigravitys-teamwork-feature/)** — 核心设计不是单纯堆更多 Agent，而是把任务切成窄上下文，让 fresh successor、critic 和 auditor 独立接力，再用形式证明、测试、物理模拟或硬件计数器验收。对 Agent 系统最值得借鉴的是“候选生成器与判定器分离”，而不是未经复现照搬官方的性能数字。

### 产品 & 工具

- **[Claude for Manufacturing 上线](https://claude.com/resources/articles/claude-for-manufacturing)** — Anthropic 发布面向制造业的插件，包含 17 个 skills，覆盖报价、质量异常、设备故障诊断、采购、设计比较和生产报告，并连接 Autodesk Fusion、Infor、Microsoft 365 与 Oracle NetSuite。写操作保留人工批准，Claude 不直接操作设备；Team/Enterprise 可安装。价值在于把行业流程打包成可审查工作流，风险则是报价、质量和供应链数据跨系统聚合后的权限与错误传播。

### 开源 & 社区

- **[alibaba/open-code-review](https://github.com/alibaba/open-code-review)** — 阿里开源的混合式代码审查工具首次进入本账本 Trending 观察：51,444 stars、3,908 forks、Apache-2.0，最新 v1.13.9。它用确定性管线保证文件选择、分组、规则匹配和评论定位，再让 LLM Agent 做上下文检索与判断；公开 AACR-Bench 含 50 个仓库、200 个真实 PR、10 种语言和 1,505 个标注问题。成熟度高于普通 prompt skill，但“1/9 token、更高 F1”等仍主要来自项目方评测，且模型凭据、MCP 工具和仓库内容需要最小权限隔离。
- **[backnotprop/plannotator](https://github.com/backnotprop/plannotator)** — 面向 Agent 规划、制品、diff 和异步反馈的人在回路工作区，连续两日 Trending 后从 10,460 增至 11,134 stars，Apache-2.0，最新 v0.28.65。新版本允许撤回尚未交付给 Agent 的消息、把 Tailscale 访问收紧到机器所有者，并改善跨机器标签与 T3 Code 接入；它也已支持 OpenClaw Inbox。仍是快速迭代的 0.x，安装器会写多种 harness 的 hooks/skills，分享、Ask AI 和远程仓库功能各有出站边界，适合隔离评测而非直接全量接管。

## 🔧 跟我们相关的

- 把 Google `/teamwork` 的关键模式加入 OpenClaw 多 Agent 验收清单：生产者与 reviewer 分离、fresh context、确定性测试优先、结果必须由外部判据证明。
- 可以在无敏感仓库中对比试跑 **Open Code Review** 与现有 SAST/人工 review，只读运行并记录召回率、误报、成本和是否读取超出 diff 的文件。
- **Plannotator** 与 OpenClaw 的异步 Inbox 很贴近当前架构，但先审计 installer、hooks、分享和 Ask AI 出站路径；不要直接接入生产凭据。
- 任何 AI 生成的 Web 应用在接入真实数据前，至少自动检查 Supabase RLS、匿名 key 权限、跨租户读取和对象存储 ACL，并由人复核。
