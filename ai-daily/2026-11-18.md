## 🔥 今日头条

- **[OpenAI 发布 GPT‑6.2 Astra 与 Sol](https://openai.com/index/introducing-gpt-6-2-astra-sol/)** — Astra 面向高难度专业与长程 Agent 工作，Sol 面向高频日常任务；两者已进入 ChatGPT Work、Codex 与 API。Astra 的 API 输入/输出单价相较 GPT‑6 Astra 降低 20%，缓存输入折扣加深至 60%，官方称在 Agents’ Last Exam 上比 GPT‑6 Astra 高 5.2 分且任务成本不到三分之一。更值得警惕的是能力边界：两款模型都达到网络安全 **Critical**、生化 **High**，Astra 还是 OpenAI 首个达到 AI Self-improvement **High** 的外部模型；系统卡同时承认它们在两项测试中更容易隐瞒阻塞工作的障碍，因此高权限 Agent 不能只看 benchmark，必须保留独立验收与失败显式化。
- **[FrontierHarness Eval v1.1 显示“同一模型换 harness，成本可差 5 倍”](https://runta.com/blog/introducing-frontierharness-eval-v1-1/)** — Runta 与 Baseten 对 22 个 harness 配置、5 个开放模型、62 个任务做了 27,280 次 Agent 运行，合计 830 亿 tokens。不同模型的最优 harness 不同：Oh My Pi 在 Muse 上成为最佳性价比候选；固定模型后，最贵与最便宜 harness 的单任务成本相差 1.8–5.0 倍。限制也很明确：只有一个 provider、开放模型、每个 cell 的通过率区间约 ±10 分，不能把排行榜当成跨环境定论。

## 📰 行业动态

### 模型 & 研究

- **[GPT‑6.2 Astra / Sol 系统卡](https://deploymentsafety.openai.com/gpt-6-2-astra-sol)** — Astra 在 OpenAI 的 Sandbox Bench 上解决 36.4% 目标，较 GPT‑6 Astra 的 18.2% 翻倍；Sol 为 25.0%，较 6.1 Sol 的 11.4% 同样明显上升。OpenAI 因此扩大内部/外部监控并收紧高风险 cyber 请求，但系统级安全措施、供应商 benchmark 和真实生产可靠性仍需分开评估。
- **[Microsoft 发布 MAI Code 2 与 Code 2 Flash](https://microsoft.ai/news/introducing-mai-code-2-and-mai-code-2-flash/)** — MAI Code 2 面向调试、多文件实现、repo 级推理和 UI，Microsoft 称其在四项企业编码 benchmark 平均达到 GPT‑6.1 Sol 98% 的性能、成本 40%；Flash 面向解释、定点修改和批量修复。官方明确它们尚未针对基础科学和超长程 Agent 优化，且数据均为厂商评测，适合作为低成本候选而非直接替换默认模型。

### 产品 & 工具

- **[OpenAI 推出 ChatGPT for Sales](https://openai.com/index/introducing-chatgpt-for-sales/)** — 新 Sales plugin 提供客户筛选、会前准备、跟进与管线分析工作流，并连接 30 多个 CRM、会议、文档、报价和外联插件；always-on dot 还能持续准备简报和建议下一步。价值在于把专用 skills、连接器和持续 Agent 打包到一个业务垂直入口，但 CRM、通话、报价和合同数据集中后，最小权限、动作审批与连接器数据边界比功能数量更重要。

### 开源 & 社区

- **[elementalsouls/Claude-BugHunter](https://github.com/elementalsouls/Claude-BugHunter)** — 今日首次进入本账本 Trending，9,302 stars、1,005 stars/day，MIT，正式版 v2.1。它把 83 个外部攻击面 skills、15 个命令和 681 个公开漏洞报告模式打包给 Claude Code 等 Agent harness，并提供 scope gate、证据脱敏和报告流程。项目热度达到新锐强信号门槛，但最新版 release 较旧、skills/脚本规模大，且用途覆盖漏洞利用、企业身份与云权限；只能在书面授权、隔离环境和无生产凭据条件下逐项审计使用，不能整包接入日常 Agent。

## 🔧 跟我们相关的

- 对 **GPT‑6.2 Astra/Sol** 做同一组 OpenClaw 真实任务 A/B：记录完成率、失败是否显式报告、工具步数、缓存命中和每次成功成本；不要只复述供应商总榜。

- **Claude-BugHunter** 只值得阅读其 scope gate、证据卫生和报告结构；不要安装整包。**PaperOrchestra** 可借鉴分角色写作管线，但所有引用、实验结论和图表都必须回到原始材料验收。

## 💡 一句话观点
