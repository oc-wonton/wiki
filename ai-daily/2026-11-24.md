## 🔥 今日头条

- **[Claude Ship 把 PR review、修复和策略审批串成一条 Agent 流水线](https://claude.com/resources/articles/introducing-claude-ship)** — Anthropic 新增 PR Steward 与 Claude Approvals：前者处理 CI 失败、冲突和 review 反馈但不批准/合并，后者依据仓库内策略文件决定自动批准或升级人工签字；官方建议先用 observe-only。它把 Coding Agent 从“写代码”推进到“维护 PR 直至可合并”，但 token 成本、错误修复循环和策略误判都需要独立验收，而且当前不支持 ZDR、HIPAA 配置或客户管理密钥组织。
- **[OpenAI 与 Cisco 开源 Shirudo，用 eBPF 为未打补丁系统部署临时防护](https://openai.com/index/introducing-shirudo/)** — Shirudo 让 Agent/工程师生成并验证称为 shield/upatch 的细粒度防护，经过人工批准、签名和 eBPF verifier 检查后加载到运行中的 Linux 服务；TPM 提供可验证的加载记录。官方控制实验称 Codex 生成的 shield 在不重启 Elasticsearch 的情况下拦截了 Java4Shell，但这只是窄场景项目方验证，不能替代正式补丁。

## 📰 行业动态

### 模型 & 研究

- **[Hugging Face 发布 Agent 评测构建与维护方法](https://huggingface.co/blog/agentic-evals)** — 文章把任务、Agent harness、固定环境、rollout、终态 verifier、trace 和报告拆成独立证据层，并展示了“最终答案正确但过程跳过必要技能”的 shortcut 如何骗过弱 grader。更关键的数据是：固定模型只改变 harness，Terminal-Bench 准确率可相差最多 29.9 个百分点；98.2% 的模型 benchmark 分数仍只由单一方报告。对 OpenClaw 的启示是，模型榜单不能替代完整系统评测，必须同时保存环境版本、轨迹、终态检查和多次运行的一致性。
- **[Ai2 发布 RoboTrack 机器人操作追踪基准、15M 合成轨迹和两个模型](https://huggingface.co/blog/allenai/robotrack)** — 307 个真实视频、2,522 条人工复核轨迹覆盖遮挡、杂乱场景与多视角；现有追踪器相较旧基准下降 3.0–6.6 AJ。项目方在 20 次移液布局实验中，RoboTracker 完整成功 17 次，高于 mask 的 8 次和光流的 5 次。样本仍小、结果主要由项目方评测，且 RoboTracker-Warp 权重仅限非商业用途。

### 产品 & 工具

- **[Anthropic Enterprise Frontier Safeguards（EFS）进入公开 beta](https://claude.com/resources/articles/zero-data-retention-with-enterprise-frontier-safeguards)** — EFS 在客户控制的 S3/GCS 数据上做跨请求自动安全监控，输入输出写入客户存储后由 Anthropic/云提供商删除，检测结果生成不含原始输入输出的 Safety Case。它试图同时解决“多轮 Agent 滥用检测”和 ZDR，但“自动系统可访问、人员不可访问”的实际边界仍取决于云权限、密钥、审计和实现验证；昨天 OpenRouter 事件已说明 ZDR 不能只看标签。
- **Claude Ship 的控制面值得注意。** 审批策略以仓库文件保存，可结合 Code Review 结果和自然语言 classifier；PR Steward 每次 push 都记录改动与撤销方式，团队可设置 review 深度与费用上限。真正风险不在能否自动修 CI，而在审批策略是否可被 PR 内容、依赖或仓库内指令影响，因此 branch protection、策略文件保护和高风险目录人工 CODEOWNERS 仍不可省。

## 🔧 跟我们相关的

- 把 Hugging Face 的评测拆解直接用于 OpenClaw：每个自动化验收至少记录任务输入、工具/模型版本、完整 trace、终态断言和重复运行一致性，避免只看“最后答案对了”。
- Claude Ship 可以观察，但不要立刻让 Approvals 接管 branch protection；先在低风险仓库启用 observe-only，并保护策略文件、CI 配置和发布目录必须人工审批。
- Shirudo 暂不部署生产；若要研究，只在隔离 VM 按官方 quickstart 验证签名、回滚、误拦截和 TPM attestation，再评估其是否值得进入主机安全路线。

## 💡 一句话观点

> 今天的共同主题不是让 Agent 获得更多权限，而是给它补上可验证的边界：PR 要有策略与人工升级，安全监控要有数据控制，评测要有轨迹和终态证据，运行时防护也必须可签名、可回滚、可证明。
