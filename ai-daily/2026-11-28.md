## 🔥 今日头条

- **[Hugging Face 把 LTX-2.5 视频生成迁到 Trainium3，单条 10 秒 2K 有声视频做到约 22–23 秒](https://huggingface.co/blog/video-trainium3)** — 实验把首次可运行版本的约 5 分 20 秒压到 22–23 秒，并开放了并行与成片脚本；真正有价值的是对 tensor/sequence parallel、图编译、host starvation 和设备解码瓶颈的逐项拆解。结果来自单台 `trn3.48xlarge`、单一模型和作者优化，且与 LTX 商业 API 的比较条件并不完全一致，不能直接外推为 Trainium3 普遍优于 GPU。

### 模型 & 研究

- **[从 prompts 到可复现短片：LTX-2.5 用首尾帧链维持跨镜头主体一致性](https://huggingface.co/blog/video-trainium3)** — 开放脚本把电影描述为 JSON shots，以 `from`/`to` 连接前后镜头，支持 seed、裁剪、字幕和声音归一；同一代码、film file 与 seed 可字节级复现。作者也明确承认每个镜头仍需多次抽样、跨镜头声音不连续、单镜头上限 20 秒，因此更适合预演和草稿，不是成片流水线。
- **机器人/自动驾驶合成数据方向值得看，但证据仍早。** 文章用真实机器人头戴相机和雪地行车片段的首秒生成替代后续，展示同一初始状态的可复现多样 continuation；模型尚未按机器人动作或车辆控制量条件化，若用于训练仍需团队基于自有 frames/actions 微调并验证物理一致性。

### 产品 & 工具

- **Trainium3 迁移案例暴露的瓶颈比最终数字更可复用。** LTX-2.5 transformer 先用 TP-4 才能装入，随后用 SP-8 把视频 token 分到 32 个 NeuronCores；host 侧 prompt encoding 从约 205 秒降到 1.4 秒，视频解码从约 357 秒降到 1.6 秒。与此同时仍存在 NaN、图加载失败、首次编译约 3 分钟和个别上游补丁未合并等限制。

## 🔧 跟我们相关的

- 若评估非 CUDA 推理，不要只比较最终 wall time：把模型加载/编译、首条与稳态延迟、host 时间、设备计算时间、输出误差和失败重试拆开记录；这篇迁移案例已经给出一套可复用的排障清单。
- 对多镜头生成任务，可以先借鉴 `film JSON + from/to frames + seed`，把镜头依赖和可复现性显式化，再考虑让 Agent 自动改写脚本；不要让 Agent 仅靠长 prompt 猜跨镜头连续性。
