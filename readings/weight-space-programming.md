# Weight-Space Programming：让强模型直接“编程”小模型权重

来源：<https://rikiyat.github.io/blog/weight-space-programming/>

阅读时间：2026-11-03。

## 核心观点

文章提出把神经网络权重视为另一种可编程介质：不是只让前沿模型生成文本、代码或训练数据，而是给它检查模型、修改张量、运行评测和迭代的工具，让它编写权重变换程序，直接改变较小模型的行为。

作者报告，GPT-6 Astra 通过这种循环修改 Qwen3.5-0.8B 约 0.016% 的权重，使 MATH-500 准确率由 7.9% 提升至 48.1%。这说明一个强模型可能把自己的部分能力“编译”为稀疏权重补丁，而不必完整重训目标模型。

## 与传统方法的区别

- Prompt engineering：权重不变，只改变输入上下文。
- Fine-tuning：使用数据、损失函数和梯度，广泛更新参数。
- LoRA：冻结基础模型，训练低秩适配器。
- Model editing：通常针对少量事实或行为做局部修改。
- Weight-space programming：由强 Agent 根据评测反馈编写并迭代权重操作程序，最终产出小而可部署的权重补丁。

“编程”是比喻：权重仍是连续张量，不像源代码具有稳定、可读的语义。结果更像自动搜索得到的模型补丁，而不是人类已经理解了每个神经元。

## 为什么重要

如果结果能泛化，能力可以从昂贵前沿模型转成便宜、低延迟、可离线部署的小模型；补丁也可能比长期 Prompt、蒸馏数据或完整 checkpoint 更小、更易分发和回滚。这把 Agent 从“写软件”推进到“写模型行为”。

## 证据边界

目前主要是作者实验，不足以证明通用方法：

1. 若 MATH-500 参与反复搜索或选择，它不再是干净的最终测试集，可能发生 benchmark overfitting。
2. 需要在未参与优化的数学集、不同 prompt、采样设置和模型版本上复测。
3. 必须检查其他能力是否退化，包括语言、知识、工具调用、安全和校准。
4. 0.016% 只说明修改稀疏，不说明因果机制可解释，也不自动意味着安全。
5. 需要多随机种子、消融、独立团队复现，并与 LoRA、蒸馏、常规微调在相同预算下比较。

## 对 OpenClaw 的启示

短期不应把它接入生产模型。可借鉴的是实验结构：强 Agent 提议补丁，确定性 benchmark 验证，独立 holdout 判定，补丁可回滚。未来若做 spike，应固定 base hash、限制可写张量、隔离运行、记录所有候选和评测，并将安全/通用能力回归作为硬门槛。
